# dnd_character_list

Личный (некоммерческий) конструктор и лист персонажа D&D 5e на Flutter. Правила, тексты и предметы берутся
из JSON API [5e14.ttg.club](https://5e14.ttg.club) (правила 2014 года). Раньше данные разбирались из html dnd.su,
но сайт работал нестабильно.

Документ описывает устройство проекта, чтобы в новой сессии не анализировать код заново.
**При заметных изменениях архитектуры или правил обновляйте его.**

## Главные договорённости

- **Без миграций.** Старые сохранённые персонажи не поддерживаются: при изменении формата `toJson`/`fromJson`
  формат просто меняется. Каждую версию считаем установкой с нуля.
- **Данные — с сайта, механика — в коде.** Тексты, таблицы и числа берутся с ttg.club. В коде остаются только
  правила, которые нельзя вывести из текста (например, эффекты черт по `slug`).
- **Источники:** предыстории, черты и предметы — «Книга игрока» (PHB). Заклинания и подклассы — все официальные
  книги (`source.group.shortName == 'Basic'`); Unearthed Arcana, homebrew и сторонние отсекаются.
  Расширенные списки и опциональные умения TCE включены всегда (на сайте они уже входят в списки классов).
- **Имена enum'ов — английские**, сериализация через `name`/`values.byName`. Русские названия только для UI —
  в `presentation/extensions/localization_extensions.dart` (`localizedName`). Исключения, которые остались от
  старого кода: `Race`, `ClassExtras`, `FightingStyle` (у последнего свой `name`/`fromName`).
- Комментарии и тексты интерфейса — на русском, ширина строки 120 (`dart format -l 120`).
- Кости пишутся кириллицей: `Dice.name` → «к8», как на сайте.

## Структура

```text
lib/
  data/
    ttg/                    клиент, кэш и мапперы ответов ttg.club в модели
    rules_repository.dart   классы, предыстории, черты, каталог предметов
    spells_repository.dart  заклинания
    sp_source.dart          сохранение персонажей (SharedPreferences, JSON)
    session/                подключение к сессии мастера (SessionSource) и снимок персонажа для боя
  domain/
    bloc/                   кубиты: создание, повышение уровня, лист персонажа, список персонажей
    models/                 Player, классы, заклинания, предметы, боевые расчёты (combat.dart)
  presentation/             экраны (auto_route), виджеты, расширения локализации
  router.dart               маршруты; router.gr.dart и injection.config.dart генерируются
test/                       тесты; support/fixtures.dart — общий тестовый персонаж и предметы,
                            fixtures/ttg/ — сокращённые реальные ответы api (support/ttg_fixtures.dart)
packages/dnd_session/       общий пакет игрока и мастера: протокол, сервер, клиент, поиск в сети
master_app/                 приложение мастера (dnd_master)
```

- DI: `get_it` + `injectable` (`getIt<RulesRepository>()` и т.п.).
- Навигация: `auto_route`. Важно: генератор переносит значения параметров по умолчанию в `router.gr.dart`
  без импортов — не используйте по умолчанию значения из других библиотек (например, `FightingStyle.values`),
  делайте параметр nullable.
- Состояние листа: `PlayerCubit` + `PlayerModel` (InheritedModel в `main_flow`).
  `PlayerModel.getPlayer` **не подписывает** виджет на изменения — только для обработчиков нажатий.
  Для значений, которые зависят от многих полей (атаки, инициатива, скорость, пассивное восприятие),
  используйте `PlayerModel.watch`; для отдельных полей — аспектные методы (`PlayerModel.inventory` и т.п.).
  Инвентарь и панель экипировки используют `BlocBuilder<PlayerCubit, Player>`.

## Сессия мастера

Связка приложений: это — для игроков, `master_app/` — менеджер битвы мастера (пока только сессия и список
игроков; дальше — инициатива, монстры мастера). Мастер создаёт сессию, игроки в той же локальной сети
подключаются кнопкой вверху экрана боя (`SessionButton` → `SessionSheet`).

- **Пакет `dnd_session`** (Flutter-пакет, путь `packages/dnd_session`, свои тесты: `cd packages/dnd_session && flutter test`):
  - `SessionHost` — сервер мастера: `HttpServer` + WebSocket на `/session`, любой свободный порт. Игрок после
    разрыва связи остаётся в списке офлайн; переподключение с тем же `playerId` обновляет запись.
  - `SessionClient` — клиент игрока: сам переподключается каждые 2 с, пока не вызван `disconnect` или мастер
    не завершил сессию. Отправляет только изменившуюся часть данных.
  - Поиск — Bonjour/mDNS (`bonsoir`), тип `_dndsession._tcp`, в TXT — версия протокола. Если поиск не работает
    (некоторые роутеры режут multicast), игрок вводит адрес «IP:порт», который показан на экране мастера.
  - Протокол — JSON-сообщения `SessionMessage` (`join`, `profile`, `state` от игрока; `welcome`, `reject`,
    `closed` от мастера). `sessionProtocolVersion` без обратной совместимости: при несовпадении мастер отклоняет
    подключение.
- **Что уходит мастеру** — только боевые данные (`data/session/player_combatant.dart`):
  `CombatantProfile` (имя, классы и уровни, характеристики, спасброски, КД, максимум хитов, инициатива,
  скорость, пассивное восприятие) — при подключении и когда меняется; `CombatantState` (хиты, спасброски от
  смерти, ячейки 1–9 уровней, ресурсы классов по `ClassExtras.name`) — при каждом изменении. Описания умений,
  предыстория, внешность и инвентарь не передаются.
- `SessionSource` (singleton) — постоянный `playerId` = id устройства (в SharedPreferences) + имя + основной
  класс. `MainFlow` пересылает каждое состояние `PlayerCubit` в `SessionSource.updatePlayer`; при выходе из
  персонажа подключение закрывается.
- Мастер: `MasterSessionSource` (`master_app/lib/data`) поверх `SessionHost` с объявлением в сети,
  экраны `StartSessionScreen` → `SessionScreen` (карточки игроков `PlayerCard`).
- Разрешения: `NSLocalNetworkUsageDescription` и `NSBonjourServices` в Info.plist (iOS и macOS) обоих
  приложений; у мастера на macOS — `network.server` и `network.client`; Android — `INTERNET`
  (`CHANGE_WIFI_MULTICAST_STATE` добавляет плагин).

## Работа с ttg.club

Описание api — `https://5e14.ttg.club/v3/api-docs` (OpenAPI). Все запросы — `POST` с JSON:
`TtgClient.post('/classes/bard')`. Списки принимают `{page, size, search, filter, order}`; `size: -1` — весь список
(`TtgClient.allItems`). Страница отдельной сущности — `POST /api/v1/<раздел>/<slug>`.

| Что | Запрос | Маппер | Модель |
| --- | --- | --- | --- |
| Классы | `/classes/bard` + каждый официальный подкласс `/classes/bard/lore` — `ClassKind.ttgLink` | `TtgClassMapper` | `ClassInfo`, `Subclass` |
| Заклинания | список `/spells`; классы — запросы с фильтром по классу (`classSpellsRequest`); описание `/spells/bless` | `TtgSpellsMapper` | `Spell`, `SpellDetails` |
| Предыстории | список `/backgrounds` (PHB) + каждая предыстория | `TtgBackgroundsMapper` | `Background` |
| Черты | список `/feats` (PHB) + каждая черта | `TtgFeatsMapper` | `Feat` |
| Метамагия | список `/options` с фильтром `classOption: METAMAGIC` (официальные книги) + каждый вариант | `TtgOptionsMapper` | `Metamagic` |
| Оружие, доспехи и щиты | списки `/weapons`, `/armors` (PHB) + каждый предмет | `TtgEquipmentMapper` | `Weapon`, `Armor`, `Shield` |
| Снаряжение, наборы, инструменты | список `/items` (PHB) + списки по категориям (`filter.category`) + ответы по наборам и инструментам | `TtgEquipmentMapper` | `Gear`, `EquipmentPack`, `Tool` |

Все загрузки — в `RulesRepository` и `SpellsRepository`; общие приёмы разбора текста — `TtgText`.
Идентификаторы — ссылки ttg в нижнем регистре: `/weapons/rapier`, `/spells/fire_bolt`, `/feats/resilient`
(`Feat.slug` — последняя часть), умения класса — `c1`, подклассы — `lore`.

**Особенности api, которые уже учтены:**

- Ссылки в html пишутся в разном регистре и с типографскими апострофами (`/items/Thieves’_Tools`) —
  сравниваются после `TtgText.normalizeLink`. Английские названия в квадратных скобках («рапира [rapier]»)
  убираются `TtgText.plainText`.
- Фильтр `/spells` требует перечислить `level` и `book`, иначе сервер отвечает 500.
- В общем списке заклинаний нет классов — по запросу с фильтром на каждый класс (`ClassKind.ttgSpellsFilterId`).
- Ответ подкласса содержит и умения класса; умения подкласса — `archetypeFeature`, описание — корневое
  умение (`traits.archetype`). В ответе подкласса `url` указывает на класс, ссылка восстанавливается из вкладок.
- `enabledArhitypeLevel` ненадёжен (у чародея 2), а в таблице 1 уровня нет «Происхождения чародея»: уровень выбора
  подкласса — самый ранний уровень его умений (`ClassInfo.subclassLevel`). Заголовок — `archetypeName`.
- Заклинания подкласса (аберрантный разум, заводная душа) — `archetypeSpellTable` → `Subclass.spells`.
- Все столбцы таблицы класса сохраняются в `ClassLevel.columns` по названию («Единицы чародейства» → «2»).
  Число вариантов метамагии — из подписи умения в таблице: «Метамагия(3)» (`ClassInfo.featureValueAt`).
- «Быстрое создание» — абзацы описания класса от абзаца с этим заголовком до таблицы или нового заголовка.
- Снаряжение предыстории порезано по всем запятым, даже внутри скобок и придаточных («карта города»,
  «в котором вы выросли») — части склеиваются. Дополнительные таблицы («Амплуа» артиста) есть только в описании.
- В ответах по отдельным предметам нет `url` — ссылка передаётся из списка. Стоимость и вес снаряжения есть
  только в ответах по предметам, поэтому у `Gear` в каталоге их нет (не 250 запросов).
- «Магическая фокусировка» и подобное без ссылки — выбор из группы снаряжения (`EquipmentCatalog.focusGroups`).
- «Собственная предыстория» — служебная запись без навыков, отбрасывается.
- В описаниях есть сноски на эррату (`<sup><a href="/rules/Errata_(PHB)">1</a></sup>`) — убираются `TtgText.html`.
- У предмета бывает несколько категорий (амулет — священный символ и фокусировка): берётся первая из
  `TtgEquipmentMapper.gearGroups`, поэтому узкие группы стоят раньше.
- При ошибке сети или неожиданном формате ответа `TtgClient.fetch` повторяет запрос до 3 раз.

**Кэш.** `TtgCache` хранит JSON в `<ApplicationSupport>/ttg/`: правила (класс, предыстории, черты, предметы) —
30 дней, при недоступности сайта берётся устаревший кэш; битый или старый по формату кэш загружается заново.
Заклинания — свой кэш в `SpellsRepository`: список на 7 дней, описания навсегда. Неудачная загрузка в памяти
не запоминается. Описания выбранных заклинаний и умения класса сохраняются в персонаже, поэтому лист работает
без сети. При входе в создание персонажа предыстории, предметы и заклинания начинают загружаться заранее
(`CreateCharacterFlow._prefetch`): первая загрузка занимает 3–6 с на раздел.

**Сетевые разрешения:** `INTERNET` в Android-манифесте, `com.apple.security.network.client` в macOS entitlements.

## Доменная модель

- `Player` — персонаж: характеристики, классы (`Specialization`), предыстория, инвентарь, экипировка
  (`armor`, `shield`, `mainWeapon`/`secondWeapon`, `mainRangeWeapon`/`secondRangeWeapon`), владения инструментами,
  личность (`Personality.traits` — по одной строке на таблицу предыстории).
  Производные значения считаются геттерами: навыки (`Skill.getBonus`: компетентность удваивает бонус мастерства,
  «Мастер на все руки» даёт половину без владения), инициатива, скорость, пассивное восприятие, владения доспехами.
- `Specialization` — класс. **Бард** полностью собран по данным сайта: умения уровня берутся из таблицы
  `ClassInfo` и сохраняются в `Bard.features` (html), выборы — `collegeId`, `fightingStyle`, `expertise`,
  `collegeSkills`, `improvements` (`AbilityScoreImprovement`: +2 к характеристикам или `ChosenFeat`).
  **Чародей** (`Sorcerer`) — так же по данным сайта; происхождение выбирается на 1 уровне (`originId`).
  Механики происхождений в коде: «Наследие драконьей крови» — `DragonAncestor` (вид урона), +1 хит за уровень,
  КД без доспеха 13 + Лов, драконий язык; «Божественная душа» — `DivineAffinity` (заклинание склонности) и
  список жреца при выборе заклинаний; «Штормовое колдовство» — Первичный язык; «Лунное чародейство» — заклинания
  фаз на 1/3/5/7/9 уровнях и «Священное пламя»; «Теневая магия» — «Тьма» на 3 уровне (эти списки есть только
  в тексте умений — `Sorcerer._originSpellsInText`). Заклинания происхождения (`originSpells`) известны всегда
  и не входят в лимит. Выборы уровней — `metamagic` (`Metamagic` с описанием с сайта, показываются в умениях),
  `improvements`; `sorceryPoints` из таблицы — ресурс `ClassExtras.sorceryPoints` на боевом экране.
  Языки классов — `Specialization.grantedLanguages`.
  Варвар, паладин и плут повышают уровень по старой логике в коде; при создании они уже берут навыки,
  инструменты и снаряжение со своих страниц. Остальные классы на экране выбора неактивны (`ClassKind.canCreate`,
  `canLevelUp`).
- **Ячейки заклинаний** (маны больше нет): максимум — `Player.spellCells` по общей таблице заклинателя
  (`spellSlotsTable`, мультикласс через `magicLevelMultiplier`), остаток — `currentSpellSlots` по уровням.
  Заклинание или умение (`Peculiarity.requiredSlot`) тратит одну ячейку выбранного уровня. «Источник магии»
  чародея: ячейка → единицы чародейства по её уровню (не выше максимума единиц), единицы → ячейка 1–5 уровня
  (`Sorcerer.spellSlotCost`), созданные ячейки могут превышать максимум. Метамагия тратит единицы
  (`Sorcerer.metamagicCost`, у «Удвоенного заклинания» — уровень заклинания). `Player.longRest` восстанавливает
  хиты, ячейки и ресурсы классов. Текущие хиты, ячейки и ресурсы, как и раньше, не сохраняются в `toJson`.
  На экране боя первой в списке идёт `SpellSlotsSection`: плитки по уровням в три колонки
  («− осталось/максимум +»). Кнопка продолжительного отдыха
  (`LongRestButton`) закреплена вверху экрана и видна, только когда что-то ниже максимума (`canRestOnLongRest`).
  В подтверждении перечисляется, что восстановится, включая счётчик класса (`LongRestButton._restoredExtra`:
  вдохновение барда, единицы чародейства). **При переводе следующего класса на данные сайта добавьте туда его
  счётчик.** Единицы чародейства — ресурс класса в сетке
  (`ClassExtras.sorceryPoints`), как вдохновение барда; конвертация и метамагия — в диалоге этого ресурса
  (`FontOfMagicActions`).
- `Feat` — текст и требования с сайта. Механика по `slug`: «Устойчивый» (спасбросок), «Одарённый» (3 навыка),
  «Языковед» (3 языка), «Посвящённый в магию» (заклинания), «Мастер оружия» (4 вида оружия, хранятся по
  `Weapon.proficiencyKey` — ссылка или название), «Крепкий», «Бдительный», «Подвижный», «Внимательный»,
  черты доспехов. Остальные — только описание.
- `Spell` — краткие поля из списка + `SpellDetails` из ответа по заклинанию. Идентификатор и сравнение — `link`.
- Предметы: `Weapon`, `Armor`, `Shield`, `Tool`, `Gear`, `EquipmentPack` (набор хранится одним предметом
  со списком содержимого), `CustomInvetoryItem` и строки. Справочник — `EquipmentCatalog`.
- Стартовое снаряжение класса — `ClassInfo.startingEquipment`: строки → варианты «а)/б)/в)» → `EquipmentRef`
  (`isChoice` для «любое простое оружие», `quantity` для «два ручных топора»).

### Боевые расчёты (`domain/models/combat.dart`)

- КД: `Specialization.armorClass` (без доспеха 10 + Лов; лёгкий + Лов; средний + Лов не больше 2; тяжёлый без Лов;
  у варвара защита без доспехов + Тел) + щит + стиль «Оборона». Отрицательная Ловкость уменьшает КД.
  `ArmorClass.parts` — слагаемые для отображения.
- Атаки (`attacks`, `attackWith`): дальнобойное — Ловкость; фехтовальное — лучшая из Силы и Ловкости;
  иначе Сила (в том числе при метании). Бонус мастерства — только при владении (`weaponProficiency`
  классов + «Мастер оружия»). Универсальное оружие двумя руками, если вторая рука свободна. Вторая рука
  без положительного модификатора к урону (кроме стиля «Сражение двумя оружиями»). «Дуэлянт» — +2 к урону.
- Экипировка (`Player.equipWeapon`, `cannotEquip`): двуручное оружие освобождает вторую руку и щит; рукопашное
  оружие во второй руке заменяет щит; во второй руке — лёгкое оружие при лёгком основном (или любое
  одноручное с чертой «Использование двух оружий»); в слот дальнего боя — стрелковое или метательное оружие
  (в UI метательное рукопашное подписывается «Метательное»). После смены основного оружия вторая рука
  перепроверяется. Удаление последнего экземпляра снимает предмет.
- Без владения доспехом/щитом и без нужной Силы для тяжёлого доспеха — предупреждения в инвентаре,
  скорость −10 футов.

## Потоки

- **Создание персонажа** — порядок шагов и условия в одном месте:
  `presentation/create_character_flow/create_character_steps.dart`. Экраны только сохраняют выбор в
  `CreateCharacterCubit` и вызывают переданный колбэк. Порядок: раса → класс (загружается `ClassInfo`) →
  подкласс, если он выбирается на 1 уровне, и его варианты (`SelectOptionScreen`: драконий предок, склонность) →
  характеристики (+ бонус расы) → предыстория → её инструменты и языки → навыки класса (без уже имеющихся) →
  навыки расы → компетентность (плут) → инструменты класса (без уже имеющихся) → стартовое снаряжение →
  заклинания → личность. После создания персонаж автоматически экипируется.
- **Повышение уровня** — `level_up_class_screen.dart`. Бард: `BardLevelUp` — шаги определяются умениями
  из строки таблицы класса (коллегия на `ClassInfo.subclassLevel`, компетентность, «Увеличение характеристик»,
  «Тайны магии», новые заговоры и заклинания по приросту столбцов). Затем необязательные замены
  (`ReplaceSpellScreen`: карточки «заклинание на замену» и «новое заклинание», выбор в диалоге с поиском):
  одного заклинания 1+ уровня — на каждом уровне (правило «Использования заклинаний»), заговора — по
  «Бардовской разносторонности» (`Bard.bardicVersatility`, TCE) на уровнях «Увеличения характеристик».
  Заменить можно только заклинания барда, известные до этого уровня; новые не могут быть уже известными
  (включая выученные на этом уровне), заговор меняется на заговор. Результат — `SpellReplacement`.
  Чародей: `SorcererLevelUp` — происхождение и его варианты (если чародей берётся мультиклассом), новые
  заклинания происхождения, «Увеличение характеристик», метамагия (`SelectMetamagicScreen`, число — из таблицы),
  заговоры и заклинания по приросту столбцов (у «Божественной души» — и из списка жреца), замена одного
  заклинания на каждом уровне, «Чародейская разносторонность» (TCE) на уровнях «Увеличения характеристик»:
  замена варианта метамагии или заговора. Общие приёмы шагов — `level_up_steps.dart` (`context.ask`, `Skippable`).
  Остальные классы — `_levelUpLegacy`.
- **Инвентарь** — `inventory_screen.dart`: деньги, панель «Экипировка» (`equipment_panel.dart`: КД, слоты,
  атаки, предупреждения), предметы по группам, карточка предмета (`item_details_sheet.dart`), добавление из
  справочника (`item_catalog_screen.dart`) или своего предмета (`Inventory_add_item_screen`).
- Тексты с сайта отображаются через `HtmlContent` (абзацы, списки, таблицы, ссылки на заклинания открывают их).

## Известные ограничения

- Повышение уровня по данным сайта сделано для барда и чародея. Вариант «Бардовской разносторонности» с заменой
  навыка компетентности не реализован — только замена заговора.
- Чародей: замена заклинаний «Псионических»/«Заводных» заклинаний аберрантного разума и заводной души не
  реализована; механики умений происхождений после 1 уровня (сопротивления, полёт, «Родство со стихией») —
  только текстом. Единицы чародейства не связаны с ячейками заклинаний («Свободное заклинательство»).
- Снаряжение предыстории — текстовые строки; у снаряжения из каталога нет стоимости и веса; боеприпасы не расходуются; вес и грузоподъёмность не считаются.
- Расовые заклинания задаются ссылками в `Race.spellForLevel` (у тифлинга пока только «Чудотворство»).
- Мультикласс в барда упрощён: один навык и один музыкальный инструмент.
